# مستندات خلاصه ملی‌پیامک

این فایل خلاصه‌ای از تصاویر مستندات ارسالی است و برای رجوع سریع داخل پروژه نگه داشته می‌شود.

## نکته مهم

- در چند متد SOAP، پارامتر `Password` به‌صورت صریح برای دریافت `ApiKey` هم معرفی شده است.
- طبق متن مستندات: برای استفاده از `APIKey` کافی است مقدار آن را به جای `Password` به متدها ارسال کنید.

## OTP

### SOAP

- Service URL:
  - `http://api.payamak-panel.com/post/Send.asmx`
- WSDL:
  - `http://api.payamak-panel.com/post/Send.asmx?wsdl`
- Method:
  - `SendOtp`

### پارامترهای `SendOtp`

- `username: string`
- `password: string`
- `code: int`
- `to: string`
- `from: string`

### کدهای بازگشتی `SendOtp`

- `recId`: شناسه ارسال
- `-111`: IP درخواست‌کننده نامعتبر است
- `-1011`: لازم است از ApiKey به جای رمز عبور استفاده شود
- `-1099`: لازم است IP برای استفاده از API مجاز شود
- `-108`: مسدود شدن IP به دلیل تلاش ناموفق استفاده از API
- `0`: نام کاربری یا رمز عبور اشتباه است
- `1`: درخواست با موفقیت انجام شد
- `2`: اعتبار کافی نیست
- `3`: محدودیت در ارسال روزانه
- `4`: محدودیت در حجم ارسال
- `5`: شماره فرستنده معتبر نیست
- `6`: سامانه در حال به‌روزرسانی است یا لینک ارسال اپراتور قطع است
- `7`: متن حاوی کلمه فیلتر شده است
- `9`: ارسال از خطوط عمومی از طریق وب سرویس امکان‌پذیر نیست
- `10`: کاربر مورد نظر فعال نیست
- `11`: ارسال نشده
- `12`: مدارک کاربر کامل نیست
- `14`: متن حاوی لینک است
- `15`: عدم وجود `1` در انتهای متن پیامک
- `16`: شماره گیرنده‌ای یافت نشد
- `17`: متن پیامک خالی است
- `18`: شماره موبایل معتبر نیست

### REST

- URL:
  - `https://rest.payamak-panel.com/api/SendSMS/SendOtp`

### پارامترهای REST برای OTP

- `username: string`
- `password: string`
- `From: string`
- `to: string`
- `code: int`

### نمونه پاسخ REST برای OTP

```json
{
  "Value": "recID",
  "RetStatus": 1,
  "StrRetStatus": "Ok"
}
```

### تفسیر پاسخ REST برای OTP

- `RetStatus = 1` یعنی ارسال موفق
- در این حالت `Value` شناسه ارسال (`recId`) است
- اگر موفق نباشد:
  - `RetStatus = 35`
  - `StrRetStatus = InvalidData`
  - و کد خطا داخل `Value` برمی‌گردد

- `500`: عدم پذیرش

## نتیجه فنی برای پروژه

- برای `OTP` بهتر است از endpoint اختصاصی `SendOtp` استفاده شود.
- برای `SMS عادی` می‌توان از `SendSimpleSMS2` یا `SendSms2` استفاده کرد.
- چون `REST OTP` پاسخ ساختاریافته‌تری دارد، برای دیباگ مناسب‌تر است.
- در متدهای SOAP، مقدار `0` لزوما به معنی «اعتبار صفر» نیست و در برخی متدها به معنی خطای احراز هویت است.

## Console API

### OTP کنسول برنامه‌نویسان

- URL نمونه:
  - `https://console.melipayamak.com/api/send/otp/<token>`
- ورودی:
  - `{ "to": "09123456789" }`
- خروجی:
  - `{ "code": "12345", "status": "..." }`

### نکته مهم درباره OTP کنسول

- این endpoint خودش کد OTP را تولید می‌کند.
- مقدار `code` باید در سامانه خودمان ذخیره و بعدا هنگام ورود کاربر اعتبارسنجی شود.
- بنابراین این endpoint با `Supabase Auth Phone OTP` به شکل built-in سازگار نیست.
- دلیلش این است که در flow داخلی Supabase، خود `GoTrue` کد OTP را تولید می‌کند و hook فقط باید همان کد را ارسال کند.
- اگر از `console OTP` استفاده کنیم، باید کل flow تایید شماره/ورود با OTP را custom پیاده‌سازی کنیم.

### ارسال پیامک پیشرفته در Console API

- URL نمونه:
  - `https://console.melipayamak.com/api/send/advanced/<token>`
- ورودی:
  - `{ "from": "5000xxx", "to": ["09123456789"], "text": "پیامک آزمایشی", "udh": "" }`
- خروجی:
  - `{ "recIds": [3741437414], "status": "..." }`

### نتیجه فنی Console API برای این پروژه

- `console OTP` برای معماری فعلی پروژه مناسب نیست، مگر اینکه OTP را کاملا custom کنیم.
- `console advanced send` برای معماری فعلی مناسب‌تر است، چون send-only است و می‌توان OTP تولیدشده توسط Supabase را با متن دلخواه خودمان ارسال کرد.
- این مسیر از نظر عملی می‌تواند بهتر از `SendOtp` قدیمی باشد، چون:
  - دیگر درگیر semantics خاص `SendOtp` نیستیم
  - نیاز به تفسیر کدهای مبهم آن endpoint کمتر می‌شود
  - احراز دسترسی با token در URL انجام می‌شود، نه username/password سنتی

## جمع‌بندی پیشنهادی

- برای حل سریع مشکل فعلی:
  - `Supabase Auth` را نگه داریم
  - hook فعلی `send-sms` را نگه داریم
  - مسیر OTP را از `SendOtp` قدیمی ملی‌پیامک به `console advanced send` تغییر دهیم
  - در متن پیامک، OTP دریافتی از payload هوک را خودمان قرار دهیم
- فقط اگر بخواهیم کل OTP را خارج از Supabase مدیریت کنیم، سراغ `console OTP` برویم.
