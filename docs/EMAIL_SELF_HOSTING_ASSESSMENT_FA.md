# بررسی میزبانی سرویس ایمیل

تاریخ: 2026-11-04 — وضعیت: بررسی خواندنی؛ هیچ نصب، انتشار یا تغییر DNS انجام نشده است.

## شواهد سرور فعلی

- Ubuntu 24.04.4، چهار هسته، ۷۹۴۱ مگابایت رم؛ هنگام بررسی ۴۵۳۲ مگابایت رم قابل استفاده بود.
- پارتیشن ۹۶ گیگابایتی، ۸۷ درصد مصرف‌شده و حدود ۱۳ گیگابایت آزاد.
- پورت‌های وب ۸۰ و ۴۴۳ در استفادهٔ سرویس وب فعلی‌اند؛ پورت‌های ایمیل ۲۵، ۴۶۵، ۵۸۷ و ۹۹۳ در خروجی بررسی listener محلی نبودند.
- اتصال TCP خروجی پورت ۲۵ به MX گوگل برقرار شد و banner دریافت شد؛ هیچ نامه‌ای ارسال نشد.
- پورت ۲۵ ورودی، PTR، اعتبار IP و تنظیم MX/SPF/DKIM/DMARC هنوز تأیید نشده‌اند.

## تصمیم پیشنهادی

خرید صندوق آماده الزامی نیست. Mailu متن‌باز است، SMTP/IMAP، مدیریت چند دامنه و سهمیه و API مدیریتی دارد؛ می‌تواند پشت رابط صندوق سازمانی پروژه قرار بگیرد. API پروژه برای ساخت صندوق اکنون یک قرارداد عمومی دارد؛ اتصال اختصاصی این قرارداد به Mailu هنوز پیاده‌سازی نشده است.

پیشنهاد مهندسی: برای استفادهٔ چندسازمانی، سرویس ایمیل از دیتابیس و سرویس‌های اصلی جدا شود. اگر همین سرور انتخاب شود، ابتدا ظرفیت دیسک و بودجهٔ ذخیره‌سازی هر صندوق و پشتیبان خارج از سرور تعیین شود؛ فضای آزاد فعلی برای نگهداری قابل اتکای چند صندوق و رشد آن‌ها کافی فرض نشده است. منابع واقعی باید پس از پاک‌سازی و تحت بار دوباره بررسی شوند. پورت‌های وب سرویس موجود نباید متوقف یا تصاحب شوند؛ استقرار نیاز به طراحی reverse proxy دارد.

mailcow نیز متن‌باز و کامل است، اما مستندات رسمی برای پیکربندی پیش‌فرض حداقل ۶ GiB رم به‌علاوهٔ ۱ GiB swap و ۲۰ GiB دیسک، بدون احتساب نامه‌ها، می‌خواهد. برای هم‌مکانی با سرویس‌های فعلی گزینهٔ پیشنهادی این بررسی نیست.

## پیش از عملیاتی‌شدن

۱. مشخص‌شدن دامنه/زیردامنهٔ صندوق‌های سازمانی و فرستندهٔ مرکزی؛ کنترل DNS و PTR و پورت‌های ورودی.
۲. فضای کافی، quota مستقل صندوق‌ها، محدودیت ارسال و جلوگیری از سوءاستفادهٔ هر سازمان.
۳. استقرار ایزولهٔ نسخهٔ پایدار، TLS معتبر، پشتیبان رمزنگاری‌شده خارج از سرور و تمرین بازگردانی.
۴. اتصال API ساخت صندوق با دسترسی محدود، ایجاد تکرارپذیر بر اساس حساب سازمان و نگهداری امن رمزها.
۵. اتصال دریافت مرحله‌ای، زمان‌بند، رسید تحویل و پایش سرویس؛ آزمون واقعی پس از مجوز صریح ارسال آزمایشی.
