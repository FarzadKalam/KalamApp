# قرارداد مرکزی شرط‌ها، متغیرها و اکشن‌ها

این سند مرجع معماری مشترک برای شرط‌ها، متغیرهای قالبی و مقداردهی اکشن‌ها است.

## منبع مرکزی

- `shared/recordRuntime.ts`: parser توکن، رندر امن، رندر type-safe و semantics مشترک شرط‌ها.
- `utils/recordVariableCatalog.ts`: فیلدهای ماژول، فیلدهای سیستمی، لیبل فارسی و حذف تکرار.
- `shared/workflowActionContract.ts`: فیلدهای قالبی، خروجی‌های موقت و modeهای مجاز همه اکشن‌ها.

مصرف‌کننده‌ها نباید parser، evaluator یا فهرست متغیر مستقل جدید بسازند. قابلیت‌های اختصاصی چاپ یا فرایند باید به‌صورت adapter روی این هسته قرار بگیرند.

## Scope

Scope گردش‌کار شامل رکورد جاری، فیلدهای سیستمی، relationهای تعریف‌شده در کانفیگ و فیلدهای رکورد مرتبط است. Scope اتوماسیون فرایند علاوه بر این موارد شامل فعالیت، مرحله قبلی و همه ماژول‌های هدف الگوی فرایند است.

فیلدهای سیستمی `system_code`، `created_at`، `created_by`، `updated_at` و `updated_by` حتی اگر در کانفیگ یک ماژول تکرار نشده باشند از provider مرکزی افزوده می‌شوند. `id` و `org_id` در picker متغیرها نمایش داده نمی‌شوند.

لیبل relation همیشه از لیبل فارسی فیلد مبدأ ساخته می‌شود؛ نمونه صحیح: `نام مشتری (موبایل اصلی)`.

## امنیت خروجی

- مقدار نمایشی با مقدار ذخیره‌سازی یکی نیست.
- UUID رابطه فقط می‌تواند داخل payload داخلی دیتابیس استفاده شود و نباید به پیام، یادداشت، بات، ایمیل، چاپ یا متن فعالیت راه پیدا کند.
- optionهای فنی باید با لیبل فارسی نمایش داده شوند؛ در نبود label معتبر، مقدار فنی خام ارسال نمی‌شود.
- token حل‌نشده در خروجی کانال‌های خارجی خالی می‌شود و به‌شکل `{{token}}` ارسال نمی‌شود.
- همه lookupهای سرور باید `org_id` داشته باشند و cacheها باید per-org باشند.

## سازگاری

کلید tokenها و JSON تنظیمات قبلی تغییر نمی‌کند. aliasهای قدیمی فقط در resolver نگهداری می‌شوند و نباید به‌عنوان گزینه تکراری در picker نمایش داده شوند. متغیرهای خروجی اکشن مانند `web_form_link` و `ai_answer` فقط در context همان اکشن قابل انتخاب‌اند.

## فرایند V2

عنوان، توضیحات، مقدار پیش‌فرض و مقدار فیلد اختصاصی هنگام ایجاد دستی، ارجاع خودکار و اجرای سرور از renderer type-safe مشترک استفاده می‌کنند. token دقیق نوع مقدار را برای ذخیره داخلی حفظ می‌کند؛ token داخل متن همیشه مقدار نمایشی امن می‌سازد.

توکن حل‌نشده در تعریف یا پیش‌نویس فرایند حذف نمی‌شود؛ همان توکن باقی می‌ماند تا هنگام ایجاد فعالیت با context کامل دوباره resolve شود. این استثنا فقط برای جلوگیری از تخریب قالب است و UUID خام همچنان در عنوان و توضیح قابل مشاهده جایگزین می‌شود.

## پیام‌رسانی و فایل‌ها

- قرارداد گیرنده یادداشت و همه اکشن‌های بات در `shared/workflowMessagingContract.ts` تعریف می‌شود: `recipient_fields` برای گیرنده از روی فیلد و `recipient_assignees` برای کاربر، نقش و گروه.
- اکشن بات گیرنده ضمنی از رکورد جاری اضافه نمی‌کند. تنظیم‌های قدیمی «گیرنده مرتبط» چون به‌صورت `recipient_fields` ذخیره شده‌اند همچنان اجرا می‌شوند، اما UI جدید گزینه تکراری تولید نمی‌کند.
- منبع پیش‌فرض اکشن‌های تازه، همه فایل‌های ستاره‌دار همان رکورد در فایل‌منیجر مرکزی است. اکشن‌های قدیمی بدون تغییر رفتار باقی می‌مانند و `attachment_fields` آن‌ها همچنان به‌عنوان مسیر سازگاری خوانده می‌شود.
- ستاره فایل در `file_entries.metadata.main_image.starred` نگهداری می‌شود و می‌تواند برای تصویر، ویدئو یا هر نوع فایل و برای بیش از یک مورد فعال باشد. مودال V2 فعالیت و فایل‌منیجر ماژول باید همین metadata و invalidation مشترک را استفاده کنند.
- لینک کوتاه رکورد از `short_links` با `link_type=generic`، metadata نوع `record` و مسیر `/r/:code` ساخته می‌شود. مسیرهای عمومی `/i`، `/d` و وب‌فرم‌ها قرارداد جداگانه دارند و نباید از resolver لینک رکورد استفاده کنند.

## تست الزامی

هر توسعه جدید باید برابری کلاینت/سرور، عدم خروج UUID یا token حل‌نشده، لیبل فارسی relation و option، dedupe متغیرها، فیلدهای سیستمی، همه modeهای مقداردهی و حفظ قالب‌های چاپ قبلی را پوشش دهد.
