# نصب سریع و ارتقا

این راهنما برای Ubuntu 24.04 LTS، معماری amd64 و سرور اختصاصی مشتری است. ویزارد ترمینال انگلیسی است. **وجود کد نصاب به معنی آماده‌بودن بستهٔ قابل تحویل نیست:** فقط انتشار امضاشده‌ای نصب شود که آزمون دیتابیس تمیز و نصب بدون شبکهٔ آن ثبت و تأیید شده است. وضعیت فعلی را در [STATUS_FA.md](STATUS_FA.md) ببینید.

## ۱. آماده‌سازی پرونده و فایل‌ها

در پنل تازه سیستم، از «نصب‌های اختصاصی» مشتری و عنوان نصب را انتخاب کنید. آدرس مقصد باید HTTPS باشد. دریافت گزارش سلامت پیش‌فرض خاموش است. برای چند سرور یک مشتری، پرونده‌های مستقل بسازید.

پس از آماده‌سازی، دو فایل دریافت می‌کنید: بستهٔ مشترک نرم‌افزار و بستهٔ تنظیمات این نصب. رمز مدیر، کلیدهای سرویس و کلید SSH داخل این فایل‌ها نیستند. لینک دریافت کوتاه‌عمر است؛ اگر قطع شد، لینک تازه بگیرید و دانلود قبلی را ادامه دهید:

```bash
curl --fail --location --continue-at - --output release.tar.gz 'REPLACE_WITH_SIGNED_DOWNLOAD_URL'
```

فایل‌ها را می‌توان با حافظهٔ فیزیکی یا ابزار انتقال فایل به مقصد برد. کلید عمومی امضای انتشار و فایل `bootstrap.py` را از مسیر مستقلِ مورد اعتماد دریافت و اثرانگشت اعلام‌شدهٔ آن‌ها را مقایسه کنید. فایل تأییدکننده را از داخل بستهٔ ناشناس اجرا نکنید.

## ۲. پیش‌نیاز مقصد

- سرور Ubuntu 24.04 amd64 با حداقل حافظه و فضای اعلام‌شده در همان انتشار؛ مقدار نمونهٔ فعلی ۸ گیگابایت حافظه و ۸۰ گیگابایت فضای آزاد است.
- Python 3 و OpenSSL در نصب پایه؛ Docker و Compose و تمام وابستگی‌های لازم باید از بسته‌های آفلاین آزموده‌شده تأمین شوند.
- DNS یا نام داخلی ثابت که روی سرور و دستگاه‌های کاربران به مقصد resolve شود؛ پورت‌های ۸۰ و ۴۴۳ آزاد باشند.
- برای گواهی موجود، فایل کامل زنجیرهٔ گواهی و کلید خصوصی متناظر را روی مقصد آماده کنید. صدور آنلاین شرط نصب نیست.

## ۳. اجرای نصب

آرشیو تنظیمات دریافتی را در پوشهٔ `configuration` باز کنید. بستهٔ مشترک را پیش از بررسی امضا اجرا نکنید. در پوشهٔ فایل‌های تحویلی:

```bash
sudo python3 bootstrap.py --archive ./release.tar.gz --trust-key ./trusted-release.pub --config ./configuration/installation.json
```

ورودی مستقل ابتدا امضا و تمام فایل‌ها را بررسی می‌کند. نصاب سپس مراحل شماره‌دار پیش‌بررسی، تنظیمات، گواهی، بارگذاری imageهای آماده، اجرای SQL با ترتیب صریح و بررسی سلامت را نمایش می‌دهد. در مقصد build، نصب npm یا pull اجباری image اجرا نمی‌شود.

رمز مدیر هنگام نصب تازه دریافت می‌شود. رازها در `/opt/kalamapp/private` ساخته و نگهداری می‌شوند. پس از موفقیت، نشانی برنامه و `/installation` نمایش داده می‌شوند. اجرای مجدد همان دستور برای ادامهٔ نصب همان پرونده است؛ نسخهٔ متفاوت باید با `upgrade` اعمال شود. فایل‌های `state.json` و `private` را حذف نکنید.

برای شبکهٔ داخلی، حالت `internal_ca` یک CA محلی و گواهی شامل نام/IP مقصد می‌سازد. فایل عمومی `/opt/kalamapp/private/tls/ca.crt` را در فهرست اعتماد سیستم‌عامل و مرورگر دستگاه‌های کاربران وارد کنید. کلید `ca.key` و `server.key` فقط روی سرور می‌مانند. زنجیرهٔ اعتماد و بازشدن برنامه را قبل از ورود اطلاعات واقعی آزمایش کنید؛ خطای TLS را با خاموش‌کردن اعتبارسنجی دور نزنید.

## ۴. نگهداری روزمره

```bash
sudo python3 /opt/kalamapp/release/installer/local/cli.py status
sudo python3 /opt/kalamapp/release/installer/local/cli.py doctor
sudo python3 /opt/kalamapp/release/installer/local/cli.py logs
```

خروجی قابل اشتراک `diagnostics.json` است. داشبورد مدیر محلی به مرکز وابسته نیست. گزارش خودکار فقط با انتخاب مشتری و تنظیم خصوصی endpoint و token روی مقصد مجاز است؛ نبود گزارش جدید به معنی خرابی نیست. هیچ کانال فرمان از راه دور یا ارتقای خودکار وجود ندارد.

## ۵. پشتیبان‌گیری و ارتقا

یک کلید بازیابی متعلق به مشتری بسازید و فایل خصوصی و رمز آن را جدا از سرور و بسته نگهداری کنید:

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -aes-256-cbc -out recovery.key
openssl pkey -in recovery.key -pubout -out recovery.pub
sudo python3 /opt/kalamapp/release/installer/local/cli.py backup --recipient-pub ./recovery.pub --file ./backup.enc
sha256sum ./backup.enc
```

پشتیبان رمزگذاری‌شده شامل دیتابیس، فایل‌ها و رازهای لازم مقصد است. checksum را همراه سوابق بازیابی جدا نگهداری کنید. اجرای backup برای سازگاری داده و فایل، سرویس‌های برنامه را موقتاً متوقف می‌کند.

بستهٔ ارتقا را نیز با ورودی مستقل تأیید کنید؛ برای استخراج بدون اجرای کد بسته می‌توان از تابع `unpack_verified` همان ورودی مورد اعتماد استفاده کرد. پوشهٔ مقصد استخراج باید خالی باشد:

```bash
python3 -c 'from pathlib import Path; from bootstrap import unpack_verified; unpack_verified(Path("upgrade.tar.gz"), Path("trusted-release.pub"), Path("upgrade-release"))'
sudo python3 /opt/kalamapp/release/installer/local/cli.py upgrade --bundle ./upgrade-release --trust-key ./trusted-release.pub --recipient-pub ./recovery.pub
```

ارتقا فقط از نسخه‌های صریحاً آزموده‌شده مجاز است و ابتدا backup می‌گیرد. خطای migration عملیات را متوقف می‌کند. بازگرداندن فایل برنامه به‌تنهایی، بازگرداندن دیتابیس نیست؛ مسیر بازیابی را ببینید.

## ۶. انتقال از ابر

فقط کلید عمومی `recovery.pub` را پیش از نخستین خروجی در پروندهٔ مرکزی ثبت کنید. کلید خصوصی به مرکز تحویل داده نمی‌شود. ابتدا خروجی آزمایشی را روی مقصد غیرفعال بازیابی کنید:

```bash
sudo python3 /opt/kalamapp/release/installer/local/cli.py import-data --file ./trial-transfer.tar.gz --recovery-key ./recovery.key
```

نصاب امضا، محدودهٔ سازمان، نسخه‌ها، روابط و فایل‌ها را بررسی و ورود یک عضو با رمز قبلی را درخواست می‌کند. فایل `restore-receipt.json` را در پروندهٔ مرکزی وارد کنید. نشست ابری منتقل نمی‌شود. MFA بدون مسیر آزموده‌شده باعث توقف انتقال است.

پس از تأیید آزمایش همان انتشار، اپراتور انتقال نهایی را ثبت می‌کند. منبع باید واقعاً در برابر نوشتن، تغییر فایل و عملیات خروجی متوقف شود. خروجی نهایی جایگزین آزمایشی می‌شود:

```bash
sudo python3 /opt/kalamapp/release/installer/local/cli.py import-data --file ./final-transfer.tar.gz --recovery-key ./recovery.key --replace-trial
```

پس از کنترل مقصد، تأیید رسید و اطمینان از توقف منبع:

```bash
sudo python3 /opt/kalamapp/release/installer/local/cli.py activate
```

این فرمان کد نصب و تأیید فقط‌خواندنی‌بودن ابر را می‌خواهد. تا قبل از تأیید مستقل سازوکار توقف خروجی در همان انتشار، بستهٔ انتقال نباید قابل انتشار باشد. دوطرفه‌کردن نوشتن، روشن‌کردن هم‌زمان دو نسخه و پاک‌کردن منبع بخشی از این نسخه نیست. خروجی خصوصی پس از ۷ روز منقضی و توسط worker حذف می‌شود.
